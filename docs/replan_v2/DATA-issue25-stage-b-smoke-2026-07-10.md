## 2. Initial target-centred imagery prefetch

The smoke requested five initial vintages from each imagery source for each
of 20 targets (100 requests per source):

| imagery source | success | failure | successful zoom | successful source TIFF bytes |
|---|---:|---:|---:|---:|
| GE Time Machine | 100/100 | 0/100 | z20 | 6.16 MiB total; 0.062 MiB mean |
| Wayback | 63/100 | 37/100 | z19 | 2.24 MiB total; 0.036 MiB mean |

TM used the `20,19,18` fallback ladder and every initial request succeeded at
z20. Wayback used `19,18`; all 63 successes were at z19. Every one of the 37
initial Wayback failures ended with the same downloader condition:

```text
GEHI succeeded but output file empty/missing at z=18
```

This is a **37% initial imagery retrieval failure rate**, not an API failure.
Across the later adaptive smoke picks, the same condition accounts for
53/138 (38.4%) Wayback observations. The smoke does not distinguish source
coverage from GEHI exporter/downloader behaviour, so it makes no stronger
coverage claim. Failed rows remain explicit missing imagery; they must not be
silently dropped or counted as Gemini/schema errors.

### 2.1 Idempotence check

The downloader cache contract was replayed once for an existing TM tuple and
once for an existing Wayback tuple. Both returned `skipped_existing`; file
counts stayed at 794 (TM tree) and 259 (Wayback tree), and the before/after
SHA256 values were identical. This verifies the committed key behaviour for
`(anchor, capture_date, version, zoom)` on both imagery-source paths without a
network re-download. Audit rows are under `smoke20/idempotence_audit/`.

### 2.2 Full-manifest initial-round prefetch

After the API smoke passed, the download was released across all 1,200 frozen
targets. This prefetch is the production initial adaptive round: five evenly
spaced vintages per target selected by the same `plan_initial_round` function
used by the scorer. Later bisection/walk-back picks remain adaptive Stage-C

Catalog and prefetch results:

| imagery source | catalog anchors / rows | initial candidates | success | failure | actual zoom | successful TIFF bytes |
|---|---:|---:|---:|---:|---:|---:|
| GE Time Machine | 1,200 / 120,223 | 6,000 | 6,000 (100%) | 0 | z20: 5,817; z19: 183 | 366.58 MiB |
| Wayback | 1,200 / 15,595 | 6,000 | 3,726 (62.1%) | 2,274 (37.9%) | z19: 3,726 | 134.72 MiB |

All 12,000 candidate keys are unique. TM has no failure and no duplicate or

The full prefetch tree, including catalogs, raw logs, caches, and 9,726 valid

## 3. End-to-end adaptive API smoke

Both imagery-source paths ran all 20 targets without a process crash. The
real-call configuration was:

```text
anchor-workers=40
qps=20
round1-model=gemini-3.1-flash-lite
round2-model=gemini-3.1-flash-lite
routing-salt-mode=target
no-verdict-store=true
```

Setting both model flags is required for every Stage-C invocation. The
verdict store remains disabled for independent repetitions.

### 3.1 Outcome summary

| imagery source | adaptive rounds | observations | binary decisions | structured model abstains | imagery download failures |
|---|---:|---:|---:|---:|---:|
| GE Time Machine | 43 | 230 | 226 | 4 | 0 |
| Wayback | 46 | 138 | 82 | 3 | 53 |

TM final states were 13 `done_appears`, 6
`done_ambiguous_nonmonotonic`, and 1 `done_ambiguous_no_recent_anchor`.
Wayback final states were 11 `done_appears`, 3

caused entirely by missing Wayback imagery, not by a hosted-model failure.

## 4. Full-run disk estimate

The smoke directories occupy 99 MiB for TM imagery products and 26 MiB for
Wayback imagery products; the completed full initial prefetch occupies
725 MiB. More usefully, the smoke products separate into raw target-centred
rasters and rendered teacher inputs, allowing the later adaptive and arm
rendering costs to be projected:

| imagery source | observed raw TIFFs | observed rendered PNGs | projected raw for 1,200 targets | projected rendered for 2,000 target-arm equivalents | projected subtotal |
|---|---:|---:|---:|---:|---:|
| TM | 282 | 230 | 0.83 GiB | 8.01 GiB | 8.85 GiB |
| Wayback | 87 | 85 | 0.20 GiB | 2.07 GiB | 2.28 GiB |
| **total** | — | — | **1.04 GiB** | **10.09 GiB** | **11.12 GiB** |

Projection rules:

- raw products scale by `1,200 / 20 = 60`;
- rendered products scale by `(400 × 3 arms + 800 × 1 winner) / 20 = 100`;
- the five repetitions reuse the same immutable rendered frame rather than
  writing five image copies;
- B0 uses the existing banked96 imagery and is excluded from new-imagery
  storage.

Reserve **14 GiB** for the full ISSUE-25 imagery tree (the 11.12 GiB
extrapolation plus approximately 20% metadata/cache/headroom). The execution
host had 765 GiB free on `/dev/sdd` at the completed Stage-B checkpoint, so
disk space is not the limiting gate. Because the projection exceeds 10 GiB,
retain the existing spot-check-before-bulk rule and verify actual growth after
the first 100 full-manifest targets.

The smoke implies approximately 16,920 successful TM source rasters after all
adaptive rounds at scale (`282/20 × 1,200`). For Wayback, expect approximately
8,280 attempted adaptive frames (`138/20 × 1,200`), of which roughly 3,180 may
remain missing if the observed 38.4% retrieval failure persists. The completed
initial prefetch already accounts for 6,000 attempts and 2,274 failures. These
are planning estimates, not a source-coverage guarantee.
