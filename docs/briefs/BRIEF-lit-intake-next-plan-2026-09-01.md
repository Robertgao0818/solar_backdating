## 1. 目标的三种版本

### V1（最低可接受）——把文献变成纪律，不把零件当成新配方

归档 SRC、停第三轮文献、把 C 类写成「条件可用」（不是面积整层弃权）、明确 Path B / 冻 Siamese / 换骨干 / 超分全部保持关闭。S2 和 r4_v2 都不新开实验设计，只承认「该做的已经写在 D1 里」。

- **能回答：** 有没有漏掉一个该立刻训的模型？没有。Related Work 该写哪四个洞？SRC 末段那四句。
- **回答不了：** 保真度会不会动；独立安装日准不准；全城每锚调用能不能降。

### V2（中间）——V1 + 把还没做的便宜件做完

在不新开 PRD 的前提下执行三件：

1. **S2 离线 EIG replay**（期望信息增益：选下一张 vintage，使得安装区间后验的不确定性下降最多）。Top-52 verdict store 已有，零 GPU、零配额。
2. **r4_v2 三 seed 照跑**（H1 质量监督修复，实现已落，bar 0.7542 / 0.7337 / 0.80 不动）。卡点是干净 commit，不是方法。
3. **C 类分层人工 + 色差探针**：在 `<15 m²` 分层样本上，人眼按帧只看芯片、不看老师，标三态（present / absent / unusable）。「可用」对小阵更严：不糊、不偏、没切半，且多边形里板和屋顶色块分得开、没有同尺度干扰。附带零训练探针：已知多边形相对邻域屋顶的亮度/颜色差，看能不能把「人眼有」和「人眼无」分开。这不是 A″（A″ 杀的是冻 embedding 模板匹配）。不改已交付的全城 Gemini 表。

S3 仍等 P2/P3 密钥，不单席位预跑。

- **能回答：** 同样老师标签下，选帧能不能省 ≥20% 调用；质量头修好后校准面动不动；小阵 0.56 是「很多片看不成色块」还是「高对比也看不稳」。
- **回答不了：** 学生对独立许可日准不准（没有许可日）；LoRA 配对是否赢逐帧（D2 尚未触发）。

### V3（理想）——把 A–G 零件组装成一篇新方法

未池化 token 轨迹 + 连续时间路径 + 区间删失损失 + 训练期拒识 + 小阵条件可用 + 独立并网日评价。文献自己说这张组装图不存在。

- **能回答：** 那四个洞能不能被同一个方法同时处理。
- **回答不了（现在）：** 密视频 TAL 掉到每年几张 GEHI 上还剩多少；老师 23% 自洽噪声下边界损失会不会再演 Path B。代价是新 PRD、新 GPU 名额、注意力从全城值守上挪走。

## 3. 最小验证实验

**探针 = V2 的第 1 件：S2 离线 replay。** 这是能最便宜判断「文献 F 是不是真的空槽」的实验。

设定（沿用 Leg-S S2，不改 bar）：

- 数据：Top-52 冻结 verdict store，只读。
- 对照：现行规则机（病例 A–R + 均匀/二分），每锚 2.56–2.69 次。
- 处理：贪心一步 EIG，`EIG(t) = H[p(τ\|D)] − E_{y_t} H[p(τ\|D, y_t)]`；τ 后验用现成 changepoint decoder。
- GO：终态区间不变或 containment 不降，**且** calls/anchor 降 ≥20%。
- 成本：1–3 个 agent 工作日，零 GPU，零配额。
- 附带（更贵、但是 C 类的真正探针）：`<15 m²` 分层人工三态 + 多边形内色差。芯片从 Top-52 Dropbox 归档抽，不回切全城热集。R1 作物和全城 wave chip 都已 release，不能假装图还在磁盘上。人工默认 **1～2 张/次**、不看老师标签；不要一次塞五张去复现老师仪器。老师当时看见的三句（详见几何 BRIEF §6）：（1）「五张」是每锚从普查日（CT `2025-01-31`）前 GEHI vintage 两端锚定、中间均匀抽的历史片，外加至多一张普查日后 GEHI `reference_only`，**不是** `aerial_2025`/Vexcel 高清；（2）一次 HTTP 调用里最多 6 个独立 image part（`gemini_max_dates_per_call=6`），不是拼贴、也不是五次分开打；（3）航测/Vexcel 普查高清几乎总是有板（库存定义），老师的「应该有板」先验挂在普查日后那张 GEHI 参考上，看不见则标 `ambiguous` 不标 absent。

r4_v2 不是探针，是已冻结合同。探针不能替代它，也不该等它。S2 不吃 GPU，与 r4_v2 不争。

S3 仍然不是探针：缺第二家族 API 就不能出 `panel_reference_v1`。文献 E 只改变它的**论文地位**（accuracy 表必须走独立参考），不降低它的工程前置。

4. **D2 LoRA（仅在 3 触发后）：** 默认花在质量/拒识头（B），不花在配对。若要试配对：必须预注册同传感器最新有板模板 × LoRA-Siamese **对照同容量逐帧 LoRA**，主指标过渡带 FP **和** FN 都必须降、CI 下界 >0。配对输了 → 配对线永久关，名额不转 TAL。
5. **V3 / TAL / Neural CDE：** 未满足「未池化输入 + 显式同时压 FP/FN 的边界损失 + unusable 作为第一输入 + 先在 3–8 帧 GEHI 烟测不塌」四条，禁止开工。区间键损失出现在任何新头上 = Path B 复发，直接 KILL。
6. **全城生产：** 已交付的 27 波表不回切。禁止把「`<15 m²` 整层弃权」写进下一 run 的生产 prereg。下一 run 若改口径，改的是「小阵可用 = 片能用 ∧ 色块分得开 ∧ 无同尺度干扰」，且必须先通过下面第 7 条。
7. **小阵条件可用（C 类证伪）：** 分层人工三态上出现下列任一，才允许把政策写成对应句子；没做完人工之前，学生表继续分面积报，**不**整层弃权、**不**整层硬判。
   - 人–人（或同一人两次）在小阵 usable 帧上对不上 → 10 px 信息不够，停训头，小阵如实报低。
   - 人能对上、Gemini/学生对不上 → 是老师/模型问题，允许零训练色差探针；仍不许开 Siamese。
   - 人只能在高对比芯片上对上 → 政策就是「能看成色块再判有无，看不成就弃权」。

## 5. 推荐 + 理由

**推荐 V2：S2 与 r4_v2 并行；C 类按条件可用、不按面积一刀切；S3 仍等密钥；V3 排队。**

这不是改 D1 的论文主线，是承认文献把 D1 里「S2 次之」的理由从「便宜」升级成了「方法新颖性还空着」。S2 零 GPU、零配额，不挡 r4_v2，也不挡全城 A3。D1 的 S5/R4 + S3 + Leg-R R1 先行仍然成立——S3 继续等密钥，r4_v2 继续等干净树，R1 字节合同继续可做。唯一的顺序修正：**不要再等 r4_v2 出结果才开 S2。**

理由按「它说什么 / 为什么重要 / 忽略会怎样」：

1. **文献没有组装图，零件对得上已有分支。** 它说的是：JUST / Neural CDE / TAL 都不是现成处方。重要，因为「查了文献」最常见的失败是立刻新开一条时序头。忽略的话，会用密视频配方在每年几张 GEHI 上重演 Path B。
2. **S2 是唯一还没做、理论现成、零成本的方法槽。** 它说的是：选哪几张 vintage 打分，文献是空的，仓库公式已写好。重要，因为全城 ~9 万非 Top-52 锚的 HTTP 量由选帧策略决定，而且这是论文方法章现在就能主张的新颖性。忽略的话，方法章只剩「蒸馏像 Gemini」——而保真度平台卡在 ~0.65，那张表不好看。
3. **小阵是色块题，不是纹理题；10 px 只在高对比能用片上够用。** 它说的是：Lechner 的 11 px / 75% 针对的是纹理分类；屋顶光伏小阵常常只是一块比周围屋顶亮或暗的色块。0.56 是学生相对老师 present 的召回，老师自己也在看同一套 10 px 糊斑，所以这个数**不能**证明「整层信息下限」，只能证明「很多片上师生都看不稳」。重要，因为整层弃权会把「高对比、色块分得开」的真阳性一起扔掉；整层硬判会把看不成色块的帧推进区间。忽略的话，会把蒸馏失败、老师乱猜、物理下限三件事继续混成 0.56。已交付全城表仍不回切。
4. **独立安装日的洞是论文表的洞，不是开普敦能填的数据。** 它说的是：遥感论文几乎没人拿屋顶许可/并网日当 date accuracy。重要，因为 fidelity-to-Gemini 不能进论文主表。忽略的话，会去加州 NEM 找「真值」却对不上 CT 屋顶。S3/CoJ 仍是本项目仅有的独立通道。
5. **D2 的 LoRA 名额更应该花在拒识，而不是配对。** PeftCD 只证明「冻编码器上的 Siamese 要 LoRA 才回得来」，不证明 LoRA 之后配对赢逐帧存在性头。A″ 已经在冻嵌入上输给逐帧对照。重要，因为只有一轮 LoRA。忽略的话，名额会花在文献自己说「无本任务证据」的那条上。

**风险最大的一条假设：** S2 离线 replay 把老师标签当模拟观测——老师在过渡带最吵，EIG 会优先打那些帧。这可能是对的（信息在刀口），也可能是浪费（那些帧本应 unusable）。探针的 GO/KILL 就是来打这条假设的。不先做 S2、先做 TAL，等于用更贵的实验去回避这条假设。

r4_v2 的工程卡点不是科学：工作区现在脏（全城 `chip_lifecycle` / TRACKER / 热集脚本）。H1 runner 拒绝 `git_dirty=true`。要跑 r4_v2，需要一次干净提交或把论文训练和全城脚本分到不同 worktree，而不是再改损失。
